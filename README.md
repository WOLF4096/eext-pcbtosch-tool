# 狼黑工具 · PCB 转原理图（专业版）

> 让反推原理图像 Layout 一样简单。

一个嘉立创EDA（专业版）扩展。它读取工程里 PCB 的器件、坐标与焊盘网络，反向生成一张可编辑的原理图：器件按你选的方式分类排布，符号自动匹配，引脚按网络拉出带网名的短线。

适用场景：接手别人只有 PCB 的板子、维修或仿制时补原理图、老项目图纸丢失后重建。

## 1. 功能一览

| 功能 | 作用 | 挂载位置 | 支持版本 |
| --- | --- | --- | --- |
| 从 PCB 转原理图 | 读 PCB 器件与网络，生成整页原理图源码，写入当前原理图页或导出工程 | 原理图 → PCB转原理图 → 从PCB转原理图 | V2.2 / V3 / V4 |
| 从 PCB 创建导线 | 在已选中的器件上，按 PCB 网络补画带网名的短线 | 原理图 → PCB转原理图 → 从PCB创建导线 | V2.2 / V3 / V4 |

两个功能互不依赖，也可以配合用：先「转原理图」把符号铺出来，再「创建导线」补连线。

## 2. 环境要求

- **编辑器**：嘉立创EDA 专业版 2.2.x、3.x、4.x。
- **安装**：扩展管理器导入 `eext-pcbtosch-tool_v*.eext`，重开客户端生效。
- **工程前提**：
  - PCB 里每个器件都要有 `Unique ID`，否则写入后与 PCB 对不上；
  - 原理图与 PCB 必须是同一个工程里**已绑定**的一对（`工程 → 原理图/PCB` 关联关系）；
  - 器件要完成**器件标准化**（器件绑定了符号），否则该元件没有可放置的符号。
- **「从 PCB 创建导线」额外要求**：PCB 与原理图在**同一个编辑器窗口**里打开。分屏/多窗口时插件取不到 PCB 数据。
- **完全不联网**：只读本地工程包，不上传任何数据。

## 3. 界面说明

窗口 640×540，自上而下四块：

| 区域 | 内容 |
| --- | --- |
| 顶部 | 标题 + 当前 EDA 版本检测结果：2.2.45 ~ 4.x 显示「功能可用」，更低或更高的主版本给橙色提醒，不在 EDA 环境时整行变红并禁用全部按钮 |
| 中部表格 | 位号 / 名称 / 封装 / 器件 / 匹配符号 / 指定符号六列，按「封装 + 器件」合并同款器件，一行可含多个位号 |
| 底部选项 | 分类方式 4 选 1：按器件 / 按位号 / 按封装 / 按元件坐标；更多选项 4 个复选：显示分类标题、尝试生成导线、启用 Y 值翻转、忽略符号错误 |
| 底部按钮 | 加载数据、构建源码、写入文档、导出文件、导出表格、导出网络 |
| 最底状态条 | 进度与结果文字（成功/失败原因都写在这里） |

**选项含义**

- **显示分类标题**：在每个分类组上方写一行组名（如 `R`、`C`、`U`）。
- **尝试生成导线**：为每个有网络的引脚画一条 40mil 短线，并附上 `NET` 属性。
- **启用 Y 值翻转**：V3/V4 的电气坐标与 V2 方向相反，默认已按版本自动勾选；只有当整页符号**上下颠倒**时才需要手动改。
- **忽略符号错误**：跳过没有符号的元件继续生成；不勾选时只要有元件缺符号就整体中止，并把对应行标红。

## 4. 使用流程：从 PCB 转原理图

1. **准备一个空白原理图页**，并确保它的原理图已绑定目标 PCB，然后切到该页。
2. 菜单 **原理图 → PCB转原理图 → 从PCB转原理图**，打开工具窗口。
3. 点 **加载数据**。插件解包当前工程的 `.epro`，定位 PCB，解析器件、封装、网络，并把同款器件合并成一行。
4. **检查表格**：
   - 「匹配符号」有值 → 可直接转换；
   - 「匹配符号」为空 → 该器件没做标准化，需要在「指定符号」里填符号名，或回 EDA 里补标准化；
   - 「指定符号」支持两种填法：符号标题精确匹配，或内置关键词 `电阻` / `无极电容` / `电感`。
5. **选分类方式**，按需要勾选选项，点 **构建源码**。构建只生成字符串，不动画布，可以反复试。
6. 确认状态条提示行数后，选择出口：
   - 画布已清空、要就地生成 → **写入文档**；
   - 元件很多、担心卡顿，或想留档 → **导出文件**；然后 **文件 → 打开 → 嘉立创EDA** 导入该 `.epro`。

> 建议第一次用大工程时先「导出文件」验证结果，再决定是否直接写入。

## 5. 四个出口：写入与导出

| 出口 | 产物 | 说明 |
| --- | --- | --- |
| 写入文档 | 直接改写当前原理图页 | 有门禁：当前文档必须是**原理图页**，否则拒绝写入并提示。写完后会清点画布上的器件数，为 0 时明确报「没有生成器件」，不会假报成功。**写入前请确保当前页是空白页** |
| 导出文件 | 一个 `.epro` 工程包 | 把生成的源码写回原工程包的 `SHEET/<原理图 uuid>/1.esch`，即**当前原理图第 1 页**，其余内容原样保留。文件名取工程名 |
| 导出表格 | `.csv` 映射表 | 导出的就是界面上看到的表格（含手填的指定符号），用于大批量转换前留档、比对 |
| 导出网络 | `.csv` 网表 | 列：唯一ID、位号、引脚编号、引脚名称、引脚网络。需要在「构建源码」之后导出，因为引脚名称来自符号文件 |

## 6. 版本兼容与源码格式

EDA 的文档源码有两套格式，插件按编辑器主版本自动切换，不需要手动选：

| 版本族 | 源码格式 | 形态 |
| --- | --- | --- |
| 2.x（含 2.2） | V2 数组格式 | 每行一个 JSON 数组，无行尾标记 |
| 3.x / 4.x | 日志格式（3 与 4 同构） | 头部与实体两段、用 `\|\|` 分隔，行尾带竖线，最后一行不带 |

两种格式的真实样例（节点编号由插件自增分配）：

```text
V2  : ["COMPONENT","e1","R.1",100,-200,0,0,{},0]
V3/4: {"type":"COMPONENT","ticket":2,"id":"e2"}||{"partId":"R.1","x":120,"y":-220,"rotation":0,...}|
```

**V3/V4 的三条硬约束**（写错任何一条，符号就会「凭空消失」）：

1. `COMPONENT` 行必须带 `attrs`（Footprints / Devices / DeviceName / FootprintName / pinClass / differentialPairClass / Symbols 七个键）——缺了 `attrs`，写入仍返回成功，但器件会被静默丢弃。
2. `ATTR` 行必须字段齐全（x / y / rotation / color / … / zIndex 全写），只写 parentId + key + value 会导致整份源码写入失败。
3. 每个器件必须有一条 `Channel ID` 属性（值可以是空串），否则整份拒写。

因此插件是**整页重新生成**源码，而不是往现有文档里追加几行；这也是「写入前请用空白页」的原因。

## 7. 使用流程：从 PCB 创建导线

1. 在原理图里**选中**一个或多个器件。
2. 菜单 **原理图 → PCB转原理图 → 从PCB创建导线**。
3. 插件自动切到 PCB 读网络，再切回原理图，比对「PCB 有哪些连接、原理图还缺哪些」，只补缺的部分。
4. 完成后底部日志面板会给出：成功引脚数、总耗时、平均每条导线耗时。

注意：

- PCB 与原理图必须在同一窗口（分屏会取不到数据）；
- 写入前会再确认一次当前文档类型，切错文档会中止而不是写坏；
- 已存在连接关系的引脚不会重复画线。

## 8. 已知限制与排错

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 点「构建源码」报「部分元件格式错误，已标红」 | 这些元件没有符号（未做器件标准化） | 在表格「指定符号」列手动指定，或回 EDA 做标准化；也可以勾「忽略符号错误」跳过它们 |
| 状态条显示写入成功，但画布上没有符号 | 当前原理图页有旧内容，V3/V4 下新旧图元冲突 | 新建一个空白原理图页，重开工具再写入 |
| 写入直接被拒 | 当前文档不是原理图页（可能是 PCB 或封装页） | 切回原理图页再写 |
| 「加载数据」报「未找到对应原理图 UUID」 | 当前页所属原理图没有绑定 PCB | 先在工程里把 PCB 与原理图绑定，或换到已绑定的原理图页 |
| 符号整体上下颠倒、导线跑到符号外面 | Y 轴方向不对 | 切换「启用 Y 值翻转」后重新构建 |
| 元件数上千时客户端卡死或 OOM | 一次性写入的源码过大 | 改用「导出文件」，用导入方式打开生成的工程 |
| 导出文件打开后只有第 1 页被替换 | 导出固定写入 `SHEET/<原理图 uuid>/1.esch` | 需要写其他页时，请在该原理图的第 1 页操作，或直接「写入文档」 |
| 「从 PCB 创建导线」提示未选中器件 | 没有在原理图里选中任何器件 | 先选中器件再执行 |
| 「从 PCB 创建导线」取不到 PCB 数据 | PCB 与原理图分屏 / 不在同一窗口 | 关掉分屏，在同一窗口打开两者 |

## 9. 常见问题

**Q：生成的原理图和 PCB 还能联动吗？**
能。插件写入的是标准图元，`Unique ID` 会一并带过去；生成后再用 EDA 原生的「从 PCB 导入变更」可补全位号、名称与自定义参数。

**Q：表格里一行有多个位号，正常吗？**
正常。同封装 + 同器件会被合并成一行显示，实际转换时按每个位号各放一个符号。

**Q：按元件坐标分类有什么用？**
尝试 1:1 还原元件在 PCB 上的相对位置，适合对照 PCB 快速核对；缺点是不做紧凑排布，整页会比较散。

**Q：会改我的工程文件吗？**
「构建源码」不会。「写入文档」改当前原理图页；「导出文件」只生成一个新文件，原工程不动。

## 10. 开发与构建

### 10.1 目录结构

```
extension.json              扩展清单（名称、版本、菜单注册）
iframe/
  PcbToSch.html             工具页面（只引产物，不放业务代码）
  css/common.css            深色主题样式（与狼黑工具主仓一致）
  js/jszip.min.js           第三方库：解包 .epro
  js/app/PcbToSch.js        构建产物（由 js/src 打包，勿手改）
  js/src/app/pcb-to-sch/    页面业务：index / model / symbolParser / layout / sourceBuilder / wirePlan
  js/src/core/              eda / version / log / util
  js/src/ui/                statusBar / progressTicker / download / toast
  js/src/sch/emitter.js     导线源码发射（与创建导线共用一份规格）
src/
  index.ts                  扩展入口：菜单函数 + 按需加载
  js/autoWire/              从 PCB 创建导线：index / netlistParser / performanceMonitor
  js/common/                logger / sourceEmitter
scripts/build-iframe.mjs    页面打包脚本（ESM → 单文件 IIFE）
config/ build/              扩展入口打包与 .eext 封装
dist/                       构建产物：index.js
```

### 10.2 命令

| 命令 | 作用 |
| --- | --- |
| `npm run build:iframe` | 把 `iframe/js/src` 打包成 `iframe/js/app/PcbToSch.js` |
| `npm run watch:iframe` | 开发时增量构建页面产物 |
| `npm run compile` | 打包扩展入口到 `dist/index.js` |
| `npm run build` | 全量：页面打包 + 入口打包 + 生成 `build/dist/eext-pcbtosch-tool_v*.eext` |
| `npm run lint` | ESLint（`iframe/js/**` 与 `src/js/**` 有意忽略，见下） |

### 10.3 与「狼黑工具」主仓的同步

本仓是从狼黑工具（`pro-api-sdk`）拆出的独立功能仓，**代码逐字节保持一致**，同步方式是整目录拷贝而不是手工改：

1. 从主仓拷贝：`iframe/js/src/{app/pcb-to-sch,core,ui,sch}`、`iframe/css/common.css`、`iframe/PcbToSch.html`、`iframe/js/jszip.min.js`、`src/js/{autoWire,common}`；
2. 按需重跑 `npm run build`；
3. 校验：`iframe/js/app/PcbToSch.js` 应与主仓产物逐字节相同（`cmp` 一下即可）。

为保住这条同步路径，移植过来的 JS 目录**不参与本仓的 ESLint 格式化**（主仓用 4 空格缩进的 prettier 风格，本仓用 tab），也不要手工「顺手优化」这些文件。

### 10.4 构建与打包规则

- 页面必须打包成单文件 IIFE：EDA 宿主把 `<script src>` 内联成无 MIME 的 blob URL，原生 ESM 在该环境不可用。
- `.edaignore` 决定哪些文件进 `.eext`：源码目录（`src/`、`iframe/js/src/`、`scripts/`、`config/`、`build/`）不进包，只留入口产物、页面产物、样式与第三方库。
- 版本号：`extension.json` 的 `version` 是平台读的权威值；`package.json` 的 `version` 供构建脚本注入，两处同时改。
